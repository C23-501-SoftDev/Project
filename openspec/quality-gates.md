# Quality gates (перед завершением change)

Цель: минимально гарантировать, что фича корректно встроена в систему и не ломает сборку.

## Обязательный минимум (backend)
Запускать из каталога `backend` в клонированном репозитории. Требуются JDK 17/21 и Maven.

1) Сборка:
- `mvn clean compile`

2) Тесты:
- `mvn test`

Один эквивалентный полный прогон: `mvn clean verify` (компиляция, тесты, упаковка JAR и отчёт JaCoCo).

3) Smoke-check API (опционально, если есть окружение):
- `mvn spring-boot:run` (dev, требуется PostgreSQL)
- затем проверить `/actuator/health`

## Полная проверка репозитория

Из корня репозитория:

```sh
node --test backend/src/test/javascript/*.test.js
openspec validate --all --strict
```

Браузерные тесты требуют запущенного приложения с PostgreSQL и тестовым администратором `admin/admin123`. Используйте отдельную тестовую БД, Git-репозиторий и blob-каталог; выключите внешние AI и уведомления. Тесты создают и изменяют данные.

```sh
cd tests/E2E
npm ci
npx playwright install chromium
E2E_BASE_URL=http://127.0.0.1:18080 npm test
```

В конфигурации Playwright: один worker, retries=0. Перед полным прогоном используйте свежую тестовую схему и JAR из текущей сборки. Не очищайте рабочую или общую БД. Обычные тестовые API-клиенты получают серверную CSRF-cookie и передают заголовок; отрицательные проверки CSRF используют отдельный raw client.

Для каждого исправления сохраняйте результаты в OpenSpec tasks и `tests/E2E/E2E_RESULTS.md`. Замер US4.4.1 описан в `tests/performance/README.md`; он дополняет функциональные тесты.

## Если нет PostgreSQL
Не менять security/авторизацию “для демо” в main-ветке.  
Для проверки без Postgres используйте тесты (`mvn test`), или поднимайте Postgres локально по `backend/readme.md`.

## Актуальность BACKTRACKER.md (если были API-изменения)
Если change добавляет, изменяет или удаляет хотя бы один API-эндпоинт:
- [ ] BACKTRACKER.md обновлён: затронутые эндпоинты отражены, статусы (`✅`/`❌`/`🔶`) актуальны
- [ ] Дата обновления в шапке BACKTRACKER.md изменена на текущую
- [ ] Если добавлена новая страница — для неё создана отдельная секция с полной таблицей API-запросов
