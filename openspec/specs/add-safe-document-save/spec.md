# add-safe-document-save Specification

## Purpose
Безопасное сохранение документа: явная обработка HTTP-статусов 200/400/401/403, debounce-автосохранение черновика, индикатор состояния сохранения, защита от потери данных через CSRF-корректные запросы.

## Requirements

### Requirement: SEC-01 — Безопасная отправка запроса сохранения

Клиентский код ДОЛЖЕН при каждом сохранении документа (ручном и автоматическом):
- читать значение Cookie `XSRF-TOKEN` через `getCsrfToken()` (уже реализована в `main.js`),
- передавать его в заголовке `X-XSRF-TOKEN`,
- использовать `credentials: 'same-origin'` (браузер включает HttpOnly Cookie `JWT` автоматически),
- НЕ формировать заголовок `Authorization` и НЕ читать значение JWT-токена из JS.

#### Scenario: Успешное сохранение через кнопку (200 OK)

- **GIVEN** пользователь открыл страницу редактирования документа `/documents/{id}/edit`
- **AND** Cookie `XSRF-TOKEN` установлен сервером
- **AND** пользователь изменил поле «Название» или тело документа
- **WHEN** пользователь нажимает кнопку «Сохранить (Ctrl+S)» или нажимает `Ctrl+S`
- **THEN** браузер отправляет `PUT /api/documents/{id}` с телом `{ content, title }`, заголовком `X-XSRF-TOKEN: <token>` и `credentials: 'same-origin'`
- **AND** сервер возвращает `200 OK`
- **AND** на странице отображается уведомление «Документ сохранён» (через `showToast`)
- **AND** индикатор автосохранения переходит в состояние «Сохранено»

#### Scenario: Сохранение через Ctrl+S

- **GIVEN** пользователь открыл страницу редактирования документа
- **WHEN** пользователь нажимает `Ctrl+S` (или `Cmd+S` на macOS)
- **THEN** поведение идентично нажатию кнопки «Сохранить» — вызывается та же функция `saveDocument()`
- **AND** событие браузера «Сохранить страницу» подавляется через `event.preventDefault()`

### Requirement: SEC-02 — Обработка ошибки аутентификации (401)

При получении ответа `401 Unauthorized` клиент ДОЛЖЕН немедленно перенаправить пользователя на страницу входа.

#### Scenario: Редирект на /login при истёкшей сессии

- **GIVEN** JWT-токен пользователя истёк или отсутствует
- **WHEN** выполняется `PUT /api/documents/{id}` (ручное или автосохранение)
- **THEN** сервер возвращает `401 Unauthorized`
- **AND** клиент выполняет `window.location.href = '/login'`
- **AND** повторная попытка отправки запроса НЕ предпринимается

### Requirement: SEC-03 — Обработка ошибки CSRF / авторизации (403)

При получении ответа `403 Forbidden` клиент ДОЛЖЕН показать сообщение о необходимости обновить страницу и НЕ предпринимать повторных попыток.

#### Scenario: Сообщение при ошибке CSRF

- **GIVEN** Cookie `XSRF-TOKEN` устарел или отсутствует (например, после долгого бездействия)
- **WHEN** выполняется `PUT /api/documents/{id}`
- **THEN** сервер возвращает `403 Forbidden`
- **AND** клиент отображает `showToast('Ошибка безопасности. Обновите страницу.', 'error')`
- **AND** повторный запрос НЕ отправляется
- **AND** перенаправление на `/login` НЕ происходит

### Requirement: SEC-04 — Отображение ошибок валидации (400)

При получении ответа `400 Bad Request` клиент ДОЛЖЕН распознать и отобразить ошибки валидации из тела ответа.

#### Scenario: Отображение ошибок валидации в UI

- **GIVEN** пользователь очистил поле «Название» (пустое `title`)
- **WHEN** пользователь нажимает «Сохранить»
- **THEN** сервер возвращает `400 Bad Request` с телом:
  ```json
  {
    "message": "Validation failed",
    "fieldErrors": [
      { "field": "title", "message": "Название не может быть пустым" }
    ]
  }
  ```
- **AND** клиент отображает все `fieldErrors[].message` через `showToast` (объединённые через `'; '`)
- **AND** кнопка «Сохранить» возвращается в активное состояние

#### Scenario: Клиентская валидация пустого заголовка

- **GIVEN** поле «Название» пустое (`title.trim() === ''`)
- **WHEN** пользователь нажимает «Сохранить» или срабатывает автосохранение
- **THEN** HTTP-запрос НЕ отправляется
- **AND** отображается `showToast('Заголовок не может быть пустым', 'error')`

### Requirement: AUTOSAVE-01 — Автосохранение черновика с debounce

Клиент ДОЛЖЕН автоматически сохранять документ через 3 секунды после последнего изменения в полях редактирования.

#### Scenario: Автосохранение после остановки ввода

- **GIVEN** пользователь открыл страницу редактирования документа
- **AND** документ загружен (поля заполнены)
- **WHEN** пользователь изменяет содержимое textarea (тело документа) или поле «Название»
- **AND** останавливает ввод на 3 секунды
- **THEN** автоматически вызывается `saveDocument({ silent: true })`
- **AND** отправляется `PUT /api/documents/{id}` с теми же заголовками безопасности (`X-XSRF-TOKEN`, `credentials: 'same-origin'`)
- **AND** индикатор автосохранения показывает «Сохранение...» во время запроса
- **AND** после успешного ответа `200 OK` индикатор показывает «Сохранено»

#### Scenario: Сброс таймера при продолжении ввода

- **GIVEN** пользователь начал вводить текст (запущен debounce-таймер 3 с)
- **WHEN** пользователь продолжает вводить текст (новое событие `input`) до истечения 3 секунд
- **THEN** предыдущий таймер сбрасывается (`clearTimeout`)
- **AND** новый таймер запускается на 3 секунды с момента последнего события
- **AND** HTTP-запрос НЕ отправляется до истечения нового таймера

#### Scenario: Автосохранение не срабатывает до первой загрузки документа

- **GIVEN** страница редактирования открылась, но `loadDocument()` ещё не завершила выполнение
- **WHEN** возникают события `input` в textarea или title
- **THEN** автосохранение НЕ запускается (флаг `documentLoaded === false`)

### Requirement: AUTOSAVE-02 — Индикатор состояния сохранения

Страница редактирования ДОЛЖНА отображать текущее состояние сохранения рядом с кнопкой «Сохранить».

#### Scenario: Отображение состояний индикатора

- **GIVEN** документ успешно загружен
- **WHEN** пользователь начинает вводить текст
- **THEN** индикатор `#autosaveStatus` показывает «Несохранённые изменения»

- **WHEN** идёт запрос сохранения (ручное или авто)
- **THEN** индикатор показывает «Сохранение...»

- **WHEN** сервер вернул `200 OK`
- **THEN** индикатор показывает «Сохранено»

- **WHEN** сервер вернул ошибку (любую, кроме 401)
- **THEN** индикатор показывает «Ошибка сохранения»
