## Why

Системные шаблоны документов сейчас задают многострочный Markdown в XML-атрибутах Liquibase `value`. XML нормализует переводы строк внутри атрибутов в пробелы, поэтому в таблицу `templates.content` попадает одна длинная строка. При создании документа из такого шаблона Markdown-парсер не распознаёт заголовки, таблицы и другие блочные элементы, а пользователь видит весь документ как плоский текст.

## What Changes

- Перенести хранение многострочного Markdown системных шаблонов на механизм, который сохраняет реальные переводы строк.
- Обновить уже вставленные системные шаблоны в существующих БД, чтобы их `content` снова стал валидным Markdown.
- Сохранить текущий API `GET /api/templates` и flow создания документов без изменения формата запросов/ответов.
- Добавить тесты, подтверждающие сохранение переносов строк в шаблонах и корректное отображение Markdown-структуры при создании документа из шаблона.

## Capabilities

### Modified Capabilities
- `document-templates`: Системные шаблоны должны хранить и отдавать Markdown без потери структурных переносов строк.

## Impact

- Затрагиваемые области: Liquibase changelog, ресурсы системных шаблонов, инициализация/обновление данных в таблице `templates`, тесты миграции или интеграционные тесты шаблонов.
- Предполагаемые файлы: `backend/src/main/resources/db/changelog/changes/005-insert-system-templates.xml`, новый changeset для исправления существующих данных, возможно `backend/src/main/resources/db/changelog/templates/*.md`.
- API не меняется; `BACKTRACKER.md` обновлять не требуется.
