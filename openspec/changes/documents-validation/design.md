## Context

Система уже поддерживает базовый CRUD для документов. Текущая реализация `DocumentService` и связанных DTO выполняет лишь поверхностные проверки (наличие полей, существование родительских сущностей). Однако для документов критически важна целостность иерархии и уникальность заголовков, чтобы избежать путаницы в навигации и повреждения структуры данных в Git.

## Goals / Non-Goals

**Goals:**
- Реализовать строгую бизнес-валидацию в `DocumentService`.
- Обеспечить возврат HTTP 422 для логических ошибок и HTTP 400 для структурных.
- Покрыть негативные сценарии (циклы, дубликаты заголовков) интеграционными тестами.

**Non-Goals:**
- Оптимизация производительности поиска документов (фокусируемся на корректности).
- Реализация сложной системы тегов или метаданных (только то, что в US1.1.3).

## Decisions

### 1. Место валидации: Service Layer
**Decision**: Вся бизнес-валидация будет сосредоточена в `com.knowledgebase.application.service.DocumentService`.
**Rationale**: Валидация требует доступа к БД (проверка уникальности заголовка, поиск родителя, проверка пространства). Слой `domain` остается чистым от Spring-инфраструктуры, а `interfaces` (контроллеры) занимаются только валидацией структуры JSON (Bean Validation).

### 2. Обработка циклических зависимостей
**Decision**: Использовать рекурсивный обход предков (или запрос предков через иерархический запрос, если поддерживается) при смене родителя.
**Rationale**: Защита данных в Git важнее скорости записи. Количество уровней вложенности документов обычно не превышает 10-15, что делает проверку дешевой.

### 3. Обработка ошибок: Custom Domain Exceptions
**Decision**: Создать исключения типа `DocumentValidationException` (extends `DomainException`).
**Rationale**: Позволяет `GlobalExceptionHandler` автоматически мапить эти ошибки в код 422 с детальным описанием полей, не смешивая их с системными ошибками 500.

### 4. Проверка уникальности заголовка
**Decision**: Добавить метод в `DocumentRepository` для поиска по `title` + `parentId` + `spaceId`.
**Rationale**: Уникальность требуется только в рамках одного уровня и одного пространства.

## Affected Components

- **application**: `DocumentService.java` (основная логика).
- **domain**: `Document.java` (возможно, добавление методов проверки), создание новых исключений.
- **interfaces**: `CreateDocumentRequest`, `UpdateDocumentRequest` (добавление аннотаций jakarta.validation), `GlobalExceptionHandler`.
- **infrastructure**: `DocumentJpaRepository` (новые query-методы).

## Risks / Trade-offs

- **[Risk]**: Гонка условий (Race Condition) при проверке уникальности заголовка. → **Mitigation**: Добавление уникального индекса в БД на уровне Liquibase для гарантированной защиты на уровне транзакции.
- **[Risk]**: Глубокая иерархия может замедлить проверку циклов. → **Mitigation**: Ограничение максимальной вложенности (например, до 20 уровней) программно.
