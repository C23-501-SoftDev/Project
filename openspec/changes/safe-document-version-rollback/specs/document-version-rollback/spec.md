## Purpose

Позволяет редактору безопасно вернуть содержимое документа к сохранённой версии, не уничтожая историю изменений и не раскрывая чужие Git-снимки.

## ADDED Requirements

### Requirement: Restore a registered document version as a new current version

Система MUST позволять пользователю с правом редактирования восстановить содержимое опубликованного документа из любой версии, зарегистрированной для того же документа. Восстановление MUST создать новую текущую версию с новым Git SHA; исходный коммит и все последующие исторические версии MUST оставаться неизменными.

#### Scenario: Editor restores a selected historical version

- **GIVEN** редактор просматривает историю опубликованного документа и выбрал зарегистрированную историческую версию
- **WHEN** он подтверждает восстановление через `POST /api/documents/{id}/versions/{gitHash}/restore`
- **THEN** система сохраняет содержимое выбранной версии как новый текущий снимок документа
- **AND** создаёт новый Git-коммит и новую запись версии, связанную с новым SHA и редактором
- **AND** возвращает информацию о новой текущей версии

#### Scenario: Restored content matches the selected version

- **GIVEN** редактор успешно восстановил зарегистрированную версию документа
- **WHEN** система читает текущий файл документа и историю версий
- **THEN** текущий файл содержит текст выбранной исторической версии
- **AND** новая запись версии ссылается на новый SHA, отличный от SHA выбранной версии
- **AND** выбранная версия остаётся доступной в истории

### Requirement: Authorize and validate rollback targets

Система MUST выполнять восстановление только для пользователя с правом `EDIT` на пространство документа и только по корректному 40-символьному SHA, зарегистрированному для этого документа.

#### Scenario: User lacks edit permission

- **WHEN** пользователь без права `EDIT` запрашивает восстановление версии документа
- **THEN** система возвращает `403 Forbidden`
- **AND** не читает выбранный Git-снимок и не создаёт Git-коммит или запись версии

#### Scenario: Version does not belong to the document

- **WHEN** запрос содержит SHA, отсутствующий среди версий указанного документа
- **THEN** система возвращает `404 Not Found`
- **AND** не раскрывает существование, содержимое или принадлежность этой версии другому документу

#### Scenario: Version hash is malformed

- **WHEN** запрос содержит SHA, не являющийся 40-символьным шестнадцатеричным идентификатором Git-коммита
- **THEN** система возвращает `400 Bad Request`
- **AND** не выполняет Git-операций или изменений в БД

### Requirement: Keep Git and database state recoverably consistent

Система MUST сериализовать изменение локального Git-репозитория, обновлять индексируемые данные документа в БД после успешного создания нового снимка и не подтверждать восстановление частично.

#### Scenario: Git write fails

- **WHEN** создание нового Git-снимка при восстановлении завершается ошибкой
- **THEN** система возвращает серверную ошибку
- **AND** не изменяет данные документа в БД и не создаёт новую запись версии

#### Scenario: Database indexing fails after Git commit

- **WHEN** Git-коммит восстановления создан, но обновление данных документа или новой записи версии в БД завершается ошибкой
- **THEN** транзакция БД откатывается и система возвращает серверную ошибку
- **AND** система журналирует SHA созданного неприкреплённого коммита для последующего восстановления
- **AND** система не выполняет Git reset или переписывание истории

### Requirement: Require deliberate user confirmation in version history

Страница истории версий MUST предоставлять действие восстановления для выбранной версии только редактору, запрашивать явное подтверждение и после успеха обновлять отображаемую историю и текущую версию без полной перезагрузки страницы.

#### Scenario: Editor cancels confirmation

- **GIVEN** редактор выбрал историческую версию и открыл подтверждение восстановления
- **WHEN** редактор отменяет действие
- **THEN** клиент не отправляет запрос восстановления
- **AND** текущий документ и история остаются без изменений

#### Scenario: Editor sees the newly created version

- **WHEN** восстановление успешно завершено
- **THEN** интерфейс сообщает об успешном восстановлении
- **AND** история отображает новую текущую версию, созданную операцией восстановления
- **AND** кнопка восстановления не доступна пользователю без права редактирования
