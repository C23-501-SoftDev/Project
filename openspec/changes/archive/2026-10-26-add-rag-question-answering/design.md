## Context
Documents already have SQL metadata, publication state, permissions and Git versions. The existing external AI client only transforms text. This change adds a separate local Ollama RAG pipeline.
## Goals / Non-Goals
Answer questions from published articles the caller can read, with citations and explicit insufficient-evidence responses. Initial scope excludes OCR, arbitrary attachment ingestion, web search and autonomous document edits.
## Implementation decisions (2026-10-26)
- Controller: POST /api/ai/ask accepts `{ question, spaceIds? }`; response `{ answer, sources, insufficientEvidence, requestId }`. Each source has documentId, title, URL, version SHA and chunk locator. JWT/CSRF and rate limits apply. Implemented validation: question 1–2000 characters and at most 20 positive space IDs. GET /api/ai/rag/status reports configured serving/index availability; GET /ask renders the question UI. API responses use Cache-Control: no-store.
- Service: RagAnswerService orchestrates retrieval, permission checks, prompt construction, generation and final source validation. Provider ports isolate embedding and generation implementations; the existing rewrite service remains separate.
- Repository/DB: PostgreSQL + [pgvector](https://github.com/pgvector/pgvector), which supports vector similarity search in PostgreSQL. pgvector 0.8.7 is verified against PostgreSQL 18.6. Migration 037 requires the explicit Liquibase context `rag`; ordinary startup and H2 tests do not need the extension. Exact cosine search avoids approximate-index ACL recall loss in this first version.
- Chunks retain documentId, spaceId, Git SHA, sourceUpdatedAt, chunk number, text, embedding model name, dimension and vector. The primary key includes document/version/model/dimension/chunk. A job replaces one document's chunks atomically after verifying its lease and current SQL source state. Model weights updated under the same mutable tag require a new local model name and reindexing; the evaluation records the model digest separately.
- Reconcile committed published documents into durable SQL jobs on a scheduled bounded scan. Source SHA, metadata timestamp, model or dimension changes schedule indexing. Jobs use SKIP LOCKED, renewable five-minute leases, at most five attempts and retry backoff. A persistent UTC daily character reservation bounds attempted indexing work. Deletion invalidates retrieval immediately through authoritative metadata filtering, then removes index rows asynchronously.
- Retrieve within authorized published documents, then re-check SQL permissions/state before calling the model. Do not rely solely on stale permissions copied into the vector index. Revalidate all sources before returning an answer; if access changes, discard the answer and request retry.
- Treat retrieved text as quoted reference material, never instructions. The server constructs source links from verified document IDs; the model cannot invent arbitrary citation URLs.
- The Ollama JSON Schema uses stable field order: answer, sourceIds, insufficientEvidence; allowed numeric source IDs are sorted. Strict response parsing rejects contradictory refusal/citation combinations, duplicate/unknown IDs, extra fields, invalid JSON and incomplete generation. Retrieved titles/text and the question cannot override the system rules; the prompt requires a concrete supporting fact and refusal when asked to execute or repeat hostile source instructions.
- RAG stays disabled by default, independently of the existing AI rewrite feature. Configure request timeouts, bounded context/output, per-user limits and cost caps before enabling. Log request IDs, timing, model and source IDs; avoid raw questions/documents in routine logs.
## Risks / Trade-offs
Exact cosine search avoids approximate-index filtering recall loss, but scans all eligible vectors and is not a large-corpus latency guarantee. The service currently loads accessible document IDs and performs repeated per-document space/permission checks before an IN query. Large corpora require SQL-side ACL filtering, fewer repeated space checks and load measurements; very large ID sets can exceed PostgreSQL bind-parameter limits. Final source revalidation must remain intact when optimizing.

Diagnostic local-model replays exposed unsupported answers and repetition of a hostile source instruction. Schema field ordering also affected constrained decoding: emitting citations before the answer could produce inconsistent refusal flags or unsafe repetition. The implementation fixes field order and strengthens the prompt; these cases remain acceptance regressions. Passing a finite adversarial set does not prove universal prompt-injection resistance or factual correctness. Deterministic ACL filtering, citation validation and plain-text rendering constrain data access/output independently of the model; the generator has no execution or browsing tools.

Only local Ollama receives excerpts. The adapter rejects external hosts, cloud model tags, redirects and system proxies; run Ollama with `OLLAMA_NO_CLOUD=1`.
## Acceptance Plan
The versioned evaluation corpus contains 15 synthetic Russian articles in two spaces and 30 labelled questions: 24 answerable and six without supporting evidence, including a hostile-source case. The real-model runner requires expected-source retrieval in top 5 for at least 90% of answerable queries, substantive answers with citations for at least 90%, the expected source cited for at least 90%, successful API responses, valid source/version/chunk citations, refusals for all six unsupported cases and no injection canary in answers. Separate Java/PostgreSQL suites check ACL leakage, source changes, queue concurrency and controlled failures. Schema/prompt changes require a complete evaluation rerun; final run metrics and model digests are recorded in its report, not inferred from test implementation. Latency includes full ask requests and is measured rather than claimed as a production SLA; local hardware/energy cost is not estimated.
## Selected local models and limits
The user selected local Ollama on 2026-10-26. Default embedding model: `qwen3-embedding:0.6b` (1024 dimensions); generation: `qwen3:4b`, temperature 0, thinking disabled, structured JSON output. Models are downloaded once; their digests are recorded in the evaluation report. No document data is sent to a paid/external API.
Timeout 90s; context 12000 characters and 8192 model tokens; output 600 tokens; topK=5; chunk1200/overlap150; per-user6requests/minute, global100requests/day,2concurrent requests per Java process; indexing1million characters/day persisted in SQL. Request quotas reset on process restart and are not shared across replicas; production horizontal scaling needs a shared limiter. Local inference has zero external API charges; CPU/GPU electricity is not estimated.
The initial publication flow has no version row. The RAG worker captures an immutable Git baseline and adds a versions row under a document row lock for such articles. Existing document mutation paths acquire the same lock before changing Git. This happens only when RAG is configured, leaves original document text unchanged and makes provenance available before indexing.
Chunks retain sourceUpdatedAt in addition to SHA: moves, restoration and metadata changes invalidate retrieval immediately even if the prior version SHA remains unchanged. Every supplied source is revalidated before and after generation, including context not cited by the model.
## Migration / Rollback
Implementation adds an opt-in extension/table migration and durable indexing jobs. Enable only after backfill and ACL tests. Disable feature flag to roll back serving; preserve original document data. Indexes can be rebuilt from Git/SQL metadata.
