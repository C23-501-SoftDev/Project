# Design: Окончательное удаление документов (Hard-delete)

## Архитектурный подход
Реализация Hard-delete опирается на существующую архитектуру бэкенда (Spring Boot) и фронтенда (React / Admin Panel). Операция является деструктивной и необратимой, поэтому требует строгой проверки прав доступа на уровне бэкенда и фронтенда, а также атомарного выполнения в транзакции.

## Изменения бэкенда (Backend)
1. **REST API / Service Layer**:
   - Добавить эндпоинт для окончательного удаления документа (например, `DELETE /api/admin/documents/{id}/hard` или аналогичный в соответствии с принятыми в проекте соглашениями административной панели).
   - Создать метод `hardDeleteDocument(Long id)` в сервисе документов.
2. **Проверка прав и статуса**:
   - Проверить, что текущий аутентифицированный пользователь обладает ролью `ADMIN`. В случае отсутствия прав вернуть ошибку доступа (`403 Forbidden`).
   - Проверить, что целевой документ находится в статусе `DELETED`. Если документ находится в статусе `DRAFT` или `PUBLISHED`, операция должна быть отклонена с ошибкой (`400 Bad Request` или аналогичной).
3. **Обработка иерархии дерева документов**:
   - Перед удалением документа найти всех его прямых дочерних элементов (`parentId == document.id`).
   - Изменить `parent_id` дочерних элементов на `parent_id` удаляемого документа (передать детей родителю удаляемого документа / деду). Если удаляемый документ был корневым узлом (`parent_id == null`), дочерние элементы становятся корневыми (`parent_id = null`).
   - Логика изменения дерева должна полностью соответствовать правилам обработки дерева при soft-delete / перемещении в корзину.
4. **Удаление связанных данных и файлов**:
   - Каскадное удаление или явное удаление связанных записей (история восстановления, привязанные файлы/версии).
   - Физическое удаление файлов с диска / хранилища, если они связаны с удаляемым документом.
5. **Транзакционность**:
   - Вся логика удаления (перепривязка детей, удаление связей, удаление записей БД, удаление файлов) оборачивается аннотацией `@Transactional`. При возникновении исключения транзакция откатывается целиком, исключая неконсистентное состояние.

## Изменения фронтенда (Frontend)
1. **Административная корзина**:
   - В компоненте интерфейса административной корзины для каждой строки/карточки документа в статусе `DELETED` добавить действие (кнопку) «Удалить навсегда» рядом с существующей кнопкой «Восстановить».
   - Ограничить отображение кнопки «Удалить навсегда» только для пользователей с ролью `ADMIN`.
2. **Подтверждение операции**:
   - При нажатии кнопки «Удалить навсегда» открывать модальное окно с предупреждением: `"Документ будет удален без возможности восстановления. Продолжить?"`.
   - При подтверждении вызывать API Hard-delete.
3. **Обновление состояния**:
   - После успешного выполнения запроса удалять документ из локального списка корзины и выводить уведомление об успехе.
