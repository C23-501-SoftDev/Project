# Design: Экран просмотра истории версий (US2.2.2)

## Архитектура и компоненты

### Backend
1. **Git Log / History API**:
   - В интерфейс `DocumentContentRepository` добавить метод `List<DocumentVersionDto> getDocumentHistory(String gitFilePath)` или `List<CommitLogEntry> getHistory(String gitFilePath)`.
   - В реализации `JGitDocumentContentRepository` использовать `git.log().addPath(gitFilePath).call()` для обхода истории коммитов конкретного файла.
   - Из каждого объекта `RevCommit` извлекать:
     - Дату и время (Commit Time / Author Time);
     - Автора (Author Ident: name, email);
     - Сообщение коммита (Full/Short Message).
2. **DTO & Controller**:
   - Создать DTO для версии документа (например, `DocumentVersionResponse`): `commitId`, `authorName`, `commitMessage`, `timestamp`.
   - Добавить эндпоинт в контроллер документов (например, `GET /api/v1/documents/{id}/history` или аналогичный существующему REST API).
   - Проверять права доступа к документу (используя существующую систему разрешений пространств и документов).

### Frontend
1. **Компонент истории версий**:
   - На странице просмотра документа (`DocumentViewPage` / аналогичный компонент) разместить вкладку, модальное окно или боковую панель «История версий».
   - При открытии панели выполнять запрос к API истории версий выбранного документа.
2. **Отображение данных**:
   - Таблица или список элементов, отображающие для каждой версии:
     - Дату и время изменения (в локальном формате);
     - Автора изменения;
     - Комментарий к коммиту.
   - Состояния загрузки (`loading`) и обработки ошибок (`error`), а также пустого списка (`empty state`).

## Модель данных и API
- Метод: `GET /api/v1/documents/{id}/history` (или соответствующий текущему эндпоинт-паттерну проекта).
- Ответ:
  ```json
  [
    {
      "commitId": "abc1234",
      "authorName": "Иван Иванов",
      "commitMessage": "Обновление требований US2.2.2",
      "timestamp": "2026-06-06T12:34:56Z"
    }
  ```

## Обеспечение качества и безопасность
- Контроль доступа: проверка прав пользователя на просмотр конкретного документа.
- Обработка краевых случаев: файл не найден в Git, у файла еще нет коммитов (новый документ).
