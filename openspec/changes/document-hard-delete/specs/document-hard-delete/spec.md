# Spec: Окончательное удаление документов (Hard-delete)

## Требования

### 1. Hard-delete документа
- **Given**: Документ находится в корзине со статусом `DELETED`, и текущий пользователь имеет роль `ADMIN`.
- **When**: Администратор вызывает операцию Hard-delete («Удалить навсегда»).
- **Then**: Документ физически удаляется из базы данных, связанные записи и файлы очищаются, а документ становится полностью недоступным через поиск, списки и прямой URL.

### 2. Ограничение доступа
- Операция Hard-delete доступна исключительно пользователям с ролью `ADMIN`.
- Если пользователь без роли `ADMIN` пытается вызвать операцию Hard-delete, система возвращает ошибку доступа, и документ остается в корзине.

### 3. Ограничение по статусу
- Hard-delete разрешен исключительно для документов в статусе `DELETED`.
- Попытки выполнить Hard-delete для документов в статусах `DRAFT` или `PUBLISHED` запрещены и отклоняются системой.

### 4. Работа с деревом документов
- При физическом удалении документа его прямые дочерние элементы не удаляются.
- Прямые дочерние элементы удаляемого документа переподключаются к родительскому элементу удаляемого документа (к деду).
- Иерархическая структура дерева сохраняется корректно.

### 5. Очистка истории и связанных сущностей
- Все связанные записи восстановления и ссылки на удаленный документ удаляются или очищаются.

### 6. Транзакционность
- Все шаги операции Hard-delete выполняются в рамках единой транзакции базы данных для предотвращения неконсистентного состояния.

### 7. Интерфейс административной корзины
- В административной корзине для документов в статусе `DELETED` отображается кнопка «Удалить навсегда» (доступная только `ADMIN`).
- Перед выполнением операции запрашивается подтверждение пользователя.
- После успешного удаления элемент исчезает из списка корзины, и выводится уведомление об успехе.
