# Спецификация: Жизненный цикл документа (Draft / Published)

## Требования

### Требование 1: Статусы документа и создание черновика
- Система должна поддерживать жизненный цикл документа со следующими статусами: `Draft` (Черновик) и `Published` (Опубликован), а также сохранять совместимость с существующим статусом `Deleted` (Удален).
- При создании нового документа система должна автоматически устанавливать статус `Draft`.
- Текущий авторизованный пользователь при создании документа должен автоматически назначаться его автором (`authorId`).

### Требование 2: Видимость и правила доступа к документам
- **Черновик (Draft)**:
  - Доступен для просмотра и редактирования только своему автору и пользователям с ролью администратора.
  - Чужие черновики не должны отображаться при получении документа по ID (`404 Not Found` или аналогичный отказ в доступе), в списках документов, результатах поиска и при пагинации.
- **Опубликован (Published)**:
  - Доступен для чтения всем пользователям, имеющим подтвержденный доступ к пространству (space) документа.
  - Пользователи без доступа к пространству не должны видеть опубликованный документ.
- **Удален (Deleted)**:
  - Существующая логика мягкого удаления (soft delete) со статусом `Deleted` должна оставаться полностью рабочей и изолированной от статусов `Draft` и `Published`.

### Требование 3: Публикация документа и переходы жизненного цикла
- Перевод документа из статуса `Draft` в статус `Published` выполняется через специальное действие (публикацию `POST /api/documents/{id}/publish`).
- Публиковать документ имеет право **только автор** данного документа либо пользователь с ролью **администратор**.
- Попытка публикации чужого черновика обычным пользователем должна завершаться ошибкой доступа (`403 Forbidden`).
- При успешной публикации статус документа меняется на `Published`, после чего он становится доступен остальным участникам пространства.
- **Допустимые переходы статусов**:
  - `DRAFT` → `DRAFT`, `PUBLISHED` или `DELETED`;
  - `PUBLISHED` → `PUBLISHED` или `DELETED`;
  - `DELETED` → `DELETED` или `DRAFT` (восстановление).
- Все остальные переходы строго запрещены на уровне backend и интерфейса.
- Обычная операция обновления документа (`PUT /api/documents/{id}`) не принимает и не изменяет статус (поле `status` удалено из `UpdateDocumentRequest`).
- Для смены статусов используются отдельные операции (публикация, удаление/архивация, восстановление).

### Требование 4: Управление статусом в пользовательском интерфейсе
- На главной странице (`document-list.html`) и странице редактирования (`document-edit.html`) отображается выпадающий список выбора статуса.
- В интерфейсе отображаются **только допустимые переходы** для текущего статуса документа и прав пользователя.
- Выпадающий список оформлен в едином стиле с существующими статусными бейджами (`.badge.draft`, `.badge.published`, `.badge.deleted`), сохраняя исходные цвета (`Draft` — желтоватый, `Published` — зеленый, `Deleted` — красный) и аккуратную стрелочку без потери текста.
- После успешной смены статуса интерфейс обновляет отображение или перезагружает страницу.

## Сценарии (Acceptance Criteria)

### Сценарий 1: Создание документа
- **Given**: Пользователь авторизован в системе как редактор.
- **When**: Редактор создаёт новый документ в пространстве.
- **Then**: 
  - Документ успешно создаётся со статусом `Draft`.
  - Пользователь сохраняется в качестве автора (`authorId`) документа.
  - Документ доступен автору для просмотра и редактирования.
  - Документ не отображается в списках, поиске и пагинации для других обычных пользователей.

### Сценарий 2: Публикация документа
- **Given**: Документ находится в статусе `Draft`.
- **When**: Автор или администратор выполняет операцию публикации документа.
- **Then**: 
  - Статус документа изменяется на `Published`.
  - Документ становится доступен для чтения всем пользователям, имеющим доступ к соответствующему пространству.

### Сценарий 3: Ограничение видимости чужих черновиков
- **Given**: Существует документ в статусе `Draft`, созданный Пользователем А.
- **When**: Пользователь Б (не являющийся автором или администратором, но имеющий доступ к пространству) запрашивает документ по ID или получает список/поиск документов.
- **Then**: 
  - Черновик не возвращается в результатах поиска, списков и пагинации.
  - При попытке прямого запроса черновика по ID Пользователем Б система возвращает ошибку отсутствия/доступа.

### Сценарий 4: Ограничение прав на публикацию
- **Given**: Документ находится в статусе `Draft`, созданный Пользователем А.
- **When**: Пользователь В (обычный пользователь пространства, не являющийся автором и не имеющий роли администратора) пытается опубликовать документ.
- **Then**: 
  - Система отклоняет запрос с ошибкой доступа (`403 Forbidden`).
  - Статус документа остается `Draft`.

### Сценарий 5: Строгие переходы и запрет недопустимых изменений через PUT
- **Given**: Документ находится в статусе `Published`.
- **When**: Пользователь пытается изменить статус обратно в `Draft` через обычное редактирование (`PUT`) или недопустимый переход.
- **Then**:
  - Система отклоняет запрос (переход запрещен на backend).
  - Обычный `PUT` запрос на обновление контента и заголовка не затрагивает статус документа.
