## Why

История версий уже имеет маршрут страницы и хранит SHA Git-коммитов, но пользователь не может увидеть, чем отличаются две ревизии. Это не позволяет быстро проверить конкретную правку и делает сохранённые версии малоценными для редактора и аудитора.

FeatureId: `document-version-diff-mode` (новая запись в `openspec/feature-registry.json`).

## What Changes

- Добавить API сравнения двух SHA одной истории документа: `GET /api/documents/{id}/diff?from={hash1}&to={hash2}`.
- Получать diff на сервере только для Git-файлов выбранного документа и преобразовывать его в безопасную структурированную модель строк и сегментов текста.
- Поддержать четыре алгоритма сравнения: посимвольный, пословный, гибридный и построчный. Гибридный алгоритм является значением по умолчанию.
- Реализовать экран истории с выбором пары версий, алгоритма и режима представления. В одной панели удалённые и добавленные части идут последовательно; в двух панелях слева отображаются удаления, справа — добавления, а неизменённые фрагменты остаются нейтральными.
- Проверять право чтения документа и принадлежность обоих SHA этому документу; не передавать клиенту произвольный Git path или неэкранированный HTML из документа.

## Capabilities

### New Capabilities

- `document-version-diff-mode`: выбор любых двух сохранённых версий доступного документа, алгоритма сравнения и наглядное сравнение их состояний для авторов текстовой документации.

### Modified Capabilities

- *(none)*

## Impact

- **Backend:** `DocumentVersionRepository`, use case/service, Git adapter, REST controller и DTO diff-ответа с сегментами; параметр выбора алгоритма.
- **Frontend:** существующий Thymeleaf-шаблон `pages/document-history.html`, его JavaScript и стили diff-представления, включая выпадающий список алгоритмов.
- **API:** read-only endpoint расширяется параметром алгоритма; требуется актуализация `BACKTRACKER.md`.
- **Dependencies:** сохранение Git-коммитов и метаданных версий (`git-commit-on-document-save`), последующая реализация списка версий для выбора SHA.
