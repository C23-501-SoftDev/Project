# Proposal: Экран просмотра истории версий (US2.2.2)

## Why
Необходимость реализации истории версий обусловлена требованиями прозрачности редактирования документов и контроля изменений. Пользователям и администраторам базы знаний важно понимать, кто, когда и какие правки вносил в документ.
Существующая реализация на уровне Git-репозитория хранила коммиты, однако у пользователей на странице просмотра документа полностью отсутствовал интерфейс для их визуального отображения. Более того, стандартный `git.log().addPath` приводил к потере истории при переименовании или перемещении файлов в архив (`.archive/`), а также захватывал посторонние коммиты проекта и OpenSpec-артефакты, что делало невозможным просмотр чистой истории конкретного документа.

## What Changes
- Backend API получения истории версий документа (`GET /api/documents/{id}/history`).
- Получение истории строго конкретного документа по его `document_id` из реляционной таблицы `versions` с полной изоляцией от других документов и глобальных коммитов репозитория.
- DTO передачи истории (`DocumentVersionResponse` / `CommitLogEntry`).
- Отображение истории на странице просмотра документа (`document-view.html`).
- Timeline-интерфейс истории с вертикальной линией и кружками-узлами.
- Отображение автора, точного времени и комментария версии в каждой карточке события.
- Отображение по умолчанию только последних 5 записей истории с интерактивной кнопкой «Показать всю историю» / «Скрыть историю» для раскрытия полного списка без повторных запросов к API.
## Ограничения и допущения
- Не затрагивать механизмы создания документов, публикации, soft-delete и hard-delete, если они не требуют модификации логики коммитов.
- Использовать существующий JGit механизм репозитория для извлечения истории коммитов конкретного документа.
