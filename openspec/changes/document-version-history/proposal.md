# Proposal: Экран просмотра истории версий (US2.2.2)

## Цель
Реализовать интерфейс и backend-поддержку для просмотра истории версий конкретного документа на основе коммитов JGit в репозитории системы. Это позволит пользователям отслеживать эволюцию документа, видеть автора изменений, дату, время и комментарий к каждому коммиту.

## Контекст и проблемы
В текущей версии системы изменения документов уже сохраняются в виде Git-коммитов через `DocumentContentRepository` (JGit). Однако у пользователей на странице просмотра документа отсутствует визуальный интерфейс для просмотра этой истории версий.

## Решение
1. **Backend**:
   - Расширить `DocumentContentRepository` (или создать метод в сервисе документов), позволяющий получать историю коммитов (логирование коммитов) для конкретного файла документа в Git (`git log`).
   - Реализовать REST API эндпоинт (например, `GET /api/documents/{id}/history` или аналогичный в соответствии с принятыми в проекте соглашениями), возвращающий список версий с полями: дата/время изменения, автор изменения (имя/email) и комментарий к коммиту.
2. **Frontend**:
   - Добавить на страницу просмотра документа отдельный блок / боковую панель «История версий».
   - Обеспечить загрузку и отображение списка версий с датой, временем, автором и комментарием в едином стиле приложения.

## Ограничения и допущения
- Не затрагивать механизмы создания документов, публикации, soft-delete и hard-delete, если они не требуют модификации логики коммитов.
- Использовать существующий JGit механизм репозитория для извлечения истории коммитов конкретного файла.
