# Экспорт документов с изображениями и вложениями

Экспорт доступен через меню **«Экспорт»** на странице документа и в таблице документов. Права на документ проверяются сервером: чужой черновик или недоступное пространство нельзя прочитать через экспорт. Отдельная настройка или внешний сервис для конвертации не нужны.

| Пункт меню | Результат | Изображения и файлы |
|---|---|---|
| HTML | Один файл `.html` | Локальные PNG/JPEG встроены в файл. Ссылки на вложения из текста превращаются в скачиваемые встроенные файлы. |
| HTML с вложениями (ZIP) | Архив с `index.html`, папкой `attachments/` и `manifest.json` | Все текущие вложения документа, включая не упомянутые в тексте. Изображения и ссылки используют относительные локальные пути. |
| PDF | Один файл `.pdf` | PNG/JPEG встроены в страницы. Произвольные бинарные вложения в PDF не прикрепляются. |
| DOCX | Один файл `.docx` | PNG/JPEG встроены как рисунки Word. Заголовки, таблицы, списки и ссылки сохраняют структуру. Произвольные файлы внутрь DOCX не прикрепляются. |

## Как подготовить и открыть выгрузку

1. Загрузите файл во вложения нужного документа.
2. Для изображения вставьте в Markdown `![Описание](/api/attachments/123/download)`, подставив ID своего вложения. Для обычного файла используйте `[Инструкция](/api/attachments/124/download)`.
3. Откройте документ, выберите нужный пункт меню «Экспорт» и дождитесь скачивания.
4. Для ZIP распакуйте **весь архив** и откройте `index.html` в браузере. Сохраните расположение папки `attachments/` относительно HTML.

HTML и распакованный ZIP открываются без работающего приложения и без его cookies. Для полной передачи документа вместе со всеми файлами используйте ZIP. Одиночный HTML включает только файлы, на которые ссылается текст; непроцитированные вложения остаются в приложении.

В PDF/DOCX ссылки на скачивание бинарных вложений остаются текстом; сами файлы передавайте через ZIP. Обычные внешние ссылки в тексте могут сохраниться как ссылки; они не становятся автономными копиями внешних страниц.

## Состав ZIP

```text
index.html
manifest.json
attachments/
  123-Схема.png
  124-инструкция.txt
```

Префикс с ID предотвращает совпадение имён. Небезопасные символы оригинального имени заменяются, длинные имена сокращаются. В архиве нет абсолютных путей, переходов `..` или путей серверного хранилища. `manifest.json` содержит версию формата и список вложений: ID, исходное имя, путь в ZIP и размер. Архив сохраняет содержимое файлов, включая те, на которые нет ссылки в Markdown; в конце `index.html` также есть список вложений.

## Поддержка изображений и границы доступа

Встроить можно PNG и JPEG, принадлежащие экспортируемому документу. Формат проверяется по содержимому и декодированию файла, а не только по расширению или заявленному MIME. При подготовке встроенных изображений данные повторно кодируются. Для PDF используются встроенные в приложение шрифты с поддержкой кириллицы.

Ссылка на вложение другого документа не разрешается через экспорт, даже если его ID указан в Markdown. Сервер использует список файлов текущего документа и не загружает чужие метаданные. Удалённое, отсутствующее, внешнее или неподдерживаемое изображение заменяется текстом «Изображение недоступно» с безопасно выведенным alt-текстом. Недоступная ссылка на вложение теряет адрес скачивания.

Удалённые HTTP(S)-картинки, `file:`-адреса, произвольные `data:`-изображения из Markdown, SVG/GIF и другие форматы не загружаются и не встраиваются как картинки. Внешние инструкции и HTML из Markdown не исполняются. Поддерживаемые обычные вложения остаются файлами в ZIP независимо от того, умеет ли экспорт рисовать их содержимое.

Перед возвратом готовой выгрузки сервер повторно проверяет доступ, состояние документа и состав вложений. Если они изменились во время подготовки, выгрузка отменяется: повторите запрос после завершения редактирования.

## Ограничения и сообщения об ошибках

Ограничения предотвращают неограниченное чтение файлов и декодирование огромных изображений:

- не более 100 вложений у документа;
- один файл — до 10 МиБ; суммарно обрабатываемые данные файлов, нормализованных изображений и повторных встраиваний ограничены бюджетами по 50 МиБ;
- не более 100 появлений изображений в тексте;
- изображение — до 6000 пикселей по каждой стороне и до 12 миллионов пикселей; суммарно уникальные декодируемые изображения — до 32 миллионов пикселей;
- Markdown документа — до 1 000 000 символов.

Превышение бюджета возвращает HTTP 413 и понятное сообщение в интерфейсе. Если файл из списка ZIP отсутствует или его размер не совпадает с метаданными, сервер возвращает контролируемую ошибку HTTP 409 и не выдаёт неполный архив. Изменение источника во время подготовки также возвращает HTTP 409. Недостаточные права возвращают HTTP 403.

## Проверка реализации

Автоматические Java-тесты проверяют встраивание изображений, ограничения, обработку недоступных файлов и права. `tests/E2E/tests/portable-export.spec.js` дополнительно проверяет реальные загрузки через UI:

- ZIP распаковывается, картинка декодируется в браузере, текстовый файл открывается через локальную ссылку;
- чистый браузерный контекст работает в offline-режиме без cookies и HTTP-запросов;
- HTML содержит локальную картинку и файл, PDF скачивается, DOCX содержит рисунок и его relationship;
- пользователь GUEST с READ только на исходное пространство не получает чужие файлы через экспорт;
- меню таблицы содержит ZIP и отображает контролируемое сообщение о превышении лимита.

Для распаковки в E2E используется стандартный `zipfile` Python 3.9+, без дополнительных npm-библиотек. Команда Python по умолчанию — `python3`; при необходимости задайте `E2E_PYTHON`. Тесты должны работать на отдельной тестовой БД, поскольку создают документы, пользователей и вложения.
