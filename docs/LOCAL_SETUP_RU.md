# Постоянный локальный запуск на macOS

Приложение, PostgreSQL и Ollama запускаются обычными процессами текущего пользователя. Рабочие данные и модели находятся в `.local/` внутри репозитория; закрытие редактора или остановка сервисов их не удаляет. Автозапуск при входе в macOS не устанавливается: после перезагрузки выполните `start`.

## Ежедневный запуск

Откройте Terminal и перейдите в свой checkout. На настроенном Mac это:

```sh
cd /Users/matusha-g/Projects/trpo
source scripts/local/env.sh
./scripts/local/stack.sh start
./scripts/local/stack.sh status
```

Откройте [приложение](http://127.0.0.1:18081) или [вопросы по статьям](http://127.0.0.1:18081/ask). Начальная загрузка модели после остановки Ollama может занять больше времени, чем последующие вопросы.

Сервисы используют только этот компьютер:

| Сервис | Адрес | Назначение |
| --- | --- | --- |
| Приложение | `http://127.0.0.1:18081` | Статьи, редактор, экспорт, RAG |
| PostgreSQL | `127.0.0.1:55434` | База `knowledge_base_rag`, роль `kb_user` |
| Ollama | `http://127.0.0.1:11434` | Локальные embeddings и ответы |

Остановка и диагностика:

```sh
./scripts/local/stack.sh status
./scripts/local/stack.sh logs
./scripts/local/stack.sh logs ollama
./scripts/local/stack.sh stop
```

`stop` останавливает управляемые процессы и сохраняет данные. Повторный `start` использует ту же базу, Git-историю, вложения и модели. Если порт занят другим процессом, команда должна сообщить конфликт: не завершайте все процессы Java/PostgreSQL/Ollama по имени.

`logs` показывает последние 100 строк журнала приложения; можно выбрать `app`, `postgres` или `ollama`. Команда не остаётся в режиме непрерывного наблюдения.

При новой пустой базе миграция создаёт администратора `admin` с паролем `admin123`; пароль меняется в управлении пользователями. Перенесённая база сохраняет существующие учётные записи и их пароли. Случайные секреты в `.local/config.env` относятся к БД и подписи JWT, а не к паролю входа в веб-интерфейс.

## Первичная подготовка и сборка

Этот workflow предназначен для нативной установки на macOS. На текущем Mac используются Java 21, PostgreSQL 18 с установленным pgvector, Maven, Node 24 и Ollama. Скрипт управления также требует `python3` и использует только его стандартную библиотеку. Для скачивания пакетов, Maven/npm-зависимостей и отсутствующих весов моделей требуется сеть; вопросы и фрагменты статей обрабатываются локально.

Недостающие Maven, Node и Ollama устанавливаются через существующий Homebrew:

```sh
brew install maven node@24 ollama
```

Java 21, PostgreSQL 18 и расширение pgvector должны быть установлены до подготовки кластера. `env.sh` выбирает доступные инструменты; он не заменяет установку недостающих зависимостей.

Для работы по правилам OpenSpec репозиторий требований также клонирован рядом: `/Users/matusha-g/Projects/Docs`. Он больше не зависит от временной диагностической копии.

Проверить выбранный набор:

```sh
source scripts/local/env.sh
java -version
mvn -version
node --version
psql --version
ollama --version
python3 --version
```

OpenSpec и Chromium уже перенесены в постоянные каталоги текущего Mac. На новой копии checkout подготовьте инструменты проверки до setup:

```sh
npm install --prefix .local/tools/openspec @fission-ai/openspec@1.2.0
cd tests/E2E
npm ci
npx playwright install chromium
cd ../..
```

Благодаря активации `env.sh` Chromium сохраняется в `.local/browsers`. Следующий setup создаёт `.local/bin/openspec` для установленного пакета. Эти инструменты нужны для проверки/ведения проекта, не для генерации RAG-ответа.

Из корня проекта:

```sh
./scripts/local/stack.sh setup
./scripts/local/stack.sh build
```

`setup` создаёт отсутствующую конфигурацию и каталоги, не заменяя уже существующие секреты и пользовательские данные. Он запускает собственный PostgreSQL для создания базы и расширения и **оставляет его работающим**: это позволяет восстановить согласованный dump перед запуском приложения. Схема приложения затем развивается штатными миграциями Liquibase. Setup не запускает Ollama/приложение, не восстанавливает демонстрационный dump поверх существующей базы и не скачивает модели. `stop` завершает и подготовленный PostgreSQL.

На настроенном Mac обе модели уже находятся в постоянном каталоге. Для новой установки без моделей сначала запустите Ollama в отдельном терминале из корня checkout:

```sh
source scripts/local/env.sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 \
  OLLAMA_MODELS="$PWD/.local/ollama-models" ollama serve
```

Во втором терминале загрузите веса:

```sh
cd /Users/matusha-g/Projects/trpo
source scripts/local/env.sh
OLLAMA_HOST=127.0.0.1:11434 ollama pull qwen3-embedding:0.6b
OLLAMA_HOST=127.0.0.1:11434 ollama pull qwen3:4b
```

Завершите ручной `ollama serve` через `Ctrl+C`, чтобы освободить порт, затем запустите управляемый стек:

```sh
./scripts/local/stack.sh start
```

Существующий управляемый Ollama повторно запускать не нужно. При нестандартном локальном порте используйте его вместо `11434` во всех командах загрузки.

Для пересборки после изменения исходников:

```sh
./scripts/local/stack.sh stop
./scripts/local/stack.sh build
./scripts/local/stack.sh start
```

Остановку выполняйте **до** переноса checkout, изменения портов или `brew upgrade`. Скрипт проверяет пользователя, время старта и точную команду управляемого процесса; после смены расположения/версии исполняемого файла он не считает старый процесс своим автоматически и сообщает несовпадение.

`build` выполняет Maven `clean verify` и атомарно заменяет `.local/app/application.jar` только после успешной сборки; работающий процесс автоматически не перезапускает. Остальные проверки — Node, Python, Playwright, PostgreSQL-интеграции и OpenSpec — выполняются по [quality gates](../openspec/quality-gates.md). Не запускайте сценарии, создающие/удаляющие тестовые данные, на постоянной базе `knowledge_base_rag`.

Установленный и проверенный набор на 26 октября 2026:

| Компонент | Версия / расположение |
| --- | --- |
| Java | Oracle JDK 21.0.7, нативная установленная JDK |
| Maven | 3.10.0, Homebrew |
| Node.js | 24.22.1, Homebrew `node@24` |

| Python | 3.15.1, установлен как зависимость Homebrew; runtime использует стандартную библиотеку |

Это фактические версии этого прогона. Последующий `brew upgrade` может их изменить.

## Что хранится на диске

| Путь относительно checkout | Содержимое |
| --- | --- |
| `.local/config.env` | Настройки и сгенерированные локальные секреты; права доступа только владельцу |
| `.local/postgres/` | Постоянный кластер PostgreSQL |
| `.local/data/git/` | Markdown и Git-история документов; это отдельный репозиторий содержимого |
| `.local/data/blobs/` | Файлы вложений |
| `.local/ollama-models/` | Веса локальных моделей |
| `.local/app/application.jar` | Собранный исполняемый backend |
| `.local/logs/app.log` | Журнал приложения |
| `.local/logs/postgres.log` | Журнал PostgreSQL |
| `.local/logs/ollama.log` | Журнал локальной модели |
| `.local/m2/` | Кэш Maven |
| `.local/browsers/` | Chromium для браузерных проверок |
| `.local/tools/openspec/` | Локальный OpenSpec CLI |

`.local/` исключён из Git: `git pull` не переносит эти данные на другой компьютер, а клонирование репозитория не восстанавливает пользовательские статьи. Сохраняйте PostgreSQL, документный Git и blob-каталог согласованным набором. Одного Git checkout исходников или копии JAR для восстановления статей недостаточно.

Не удаляйте `.local/` для «починки» запуска. Перед переносом checkout остановите стек; пути runtime вычисляются относительно checkout. Копирование работающего PostgreSQL-кластера обычной файловой командой не является согласованным backup.

## Настройки и RAG

Параметры локального окружения находятся в `.local/config.env` в формате `KEY=VALUE`: обычные значения без кавычек, `export` и shell-команд. Скрипт читает разрешённые настройки как данные, не исполняет файл как shell-код. Не публикуйте файл и не вставляйте его целиком в сообщения или issue.

Разрешённые ключи: `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `APP_PORT`, `OLLAMA_PORT`, `APP_JWT_SECRET_KEY`, `RAG_REQUESTS_PER_MINUTE`, `RAG_DAILY_REQUESTS`. Квоты нового окружения — 6 вопросов в минуту на пользователя и 100 вопросов в сутки на процесс. Для смены портов, JWT-секрета или квот сначала остановите стек, затем измените значение и запустите снова. В этом профиле используется именно `APP_JWT_SECRET_KEY`.

Изменение `DB_PASSWORD` только в файле **не меняет пароль существующей роли PostgreSQL** и приведёт к ошибке подключения. Пароль роли меняют отдельно через согласованную административную операцию `ALTER ROLE` и обновляют конфигурацию; setup не перезаписывает пароль существующего кластера. Для другого `DB_NAME` потребуется setup новой базы, а существующие данные сами в неё не переместятся. Смена `DB_USERNAME` также требует отдельной подготовки роли и её прав, поэтому это не обычная настройка ежедневного запуска.

Локальный набор включает:

- `RAG_ENABLED=true` и Liquibase context `rag` для векторного индекса;
- embedding-модель `qwen3-embedding:0.6b`, размерность 1024;
- модель ответа `qwen3:4b`;
- `OLLAMA_NO_CLOUD=1`, `AI_ENABLED=false`, `NOTIFICATIONS_ENABLED=false`.

Внешний AI-помощник переписывания и SMTP выключены. RAG отвечает только по доступным опубликованным статьям; новые и изменённые статьи индексируются в фоне. Параметры поиска, квоты, диагностика очереди и ошибки API описаны в [RAG_LOCAL.md](RAG_LOCAL.md). Наличие запущенного Ollama само по себе не означает, что вся очередь индексации уже обработана.

## Сохранение существующих демонстрационных данных

Перенос временного демонстрационного стенда выполняется один раз: останавливаются его писатели, сохраняются dump PostgreSQL и соответствующие Git/blob-каталоги, затем набор восстанавливается в подготовленное постоянное окружение. Исходный набор сохраняется для отката до успешной проверки.

При переносе 26 октября сверены полные отпечатки строк: **15 документов, 15 версий, 2 пространства, 1 пользователь, 0 вложений**. Все 15 ссылок `Git SHA:path` разрешаются в перенесённом репозитории; `git fsck` прошёл. Вложения в исходном демонстрационном корпусе отсутствовали, поэтому этот перенос не доказывает восстановление непустого blob-каталога. Индекс содержит 15 заданий `DONE`, расширение `vector` имеет версию 0.8.7.

Исходный согласованный набор сохранён локально в `.local/backups/2026-10-26-before-migration/`: `knowledge_base_rag.dump`, `content.tar`, `manifest.json` и `ollama-models.json`. Повторные `setup`/`start` не повторяют импорт. Обычные новые статьи, созданные после переноса, остаются в постоянной базе.

Это разовая миграция текущего корпуса, не сервис автоматических резервных копий. При откате нужно возвращать согласованный набор PostgreSQL/Git/blob, а не выбирать каждую часть из разного момента времени.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Команда `mvn`, `node`, `psql` или `ollama` не найдена | Выполните `source scripts/local/env.sh` из checkout; проверьте наличие соответствующего пакета |
| Занят 18081, 55434 или 11434 | Посмотрите `stack.sh status` и владельца порта; завершите только известный старый стенд, а не чужой сервис |
| Приложение не стало готово | `stack.sh logs`, затем `.local/logs/app.log`: доступ к БД, migrations, Git/blob-пути |
| PostgreSQL не запускается | `.local/logs/postgres.log`, права на `.local/postgres`, свободное место и отсутствие другого процесса этого кластера |
| RAG недоступен или возвращает ошибку провайдера | Статус Ollama, наличие обеих моделей, `.local/logs/ollama.log`; затем [очередь RAG](RAG_LOCAL.md#диагностика-и-откат) |
| RAG ещё не знает новую статью | Статья опубликована, пользователю доступно пространство; дождитесь фоновой индексации и проверьте `rag_index_jobs` |
| После смены JWT-секрета требуется вход | Существующие JWT больше не подходят; войдите заново через страницу login |

Для чтения журналов без запуска дополнительных сервисов:

```sh
tail -n 80 .local/logs/app.log
tail -n 80 .local/logs/postgres.log
tail -n 80 .local/logs/ollama.log
```

## Проверка установки и границы

На постоянном стенде проверены readiness/health всех трёх сервисов, фактические loopback listeners, вход администратора, чтение статьи и истории. Повторный setup сохранил SHA конфигурации; попытка start при занятом чужим Ollama порте была отклонена без остановки чужого процесса. После его явной остановки управляемый стек успешно запущен.

Повторный start сохранил PID уже работающих процессов. Затем полный stop корректно завершил только управляемые приложение/Ollama/PostgreSQL; посторонние исходный PostgreSQL и E2E-приложение остались работать. Следующий start создал новые процессы всех трёх сервисов, каждый слушает `127.0.0.1`. SHA конфигурации и полные отпечатки документов/версий/вложений/пространств/пользователей после restart совпали с сохранённым набором; вход, чтение статьи и истории снова прошли.

Реальный RAG smoke **до и после stop/start** на вопрос о хранении резервных копий и логов вернул **14 и 7 дней**, сославшись на статьи **9 и 14**; серверные ссылки и Git SHA проверены. Digests перенесённых моделей совпали с исходными. Пользовательский стек оставлен включённым.

После завершения проверок временное E2E-приложение и прежний неиспользуемый PostgreSQL на 55433 отдельно остановлены; их исходные данные и согласованный backup сохранены. Рабочий постоянный PostgreSQL использует 55434.

Полная регрессия прошла на отдельной базе `knowledge_base_local_setup_test` и тестовом приложении на 18080: **281 Java**, включая **17 PostgreSQL/pgvector**, **12 Node, 7 Python-проверок RAG и 158 Playwright**; ошибок и пропусков нет, Playwright без повторов. Отдельно прошли **12 проверок runtime**; оба Python-набора подтверждены на установленном Python 3.15.1. Сам `scripts/local/stack.sh build` также прошёл 281 Java-тест, включая 17 PostgreSQL-проверок, и атомарно установил JAR. Строгая проверка OpenSpec через постоянный wrapper: **37/37**. [Зафиксированные результаты](../tests/E2E/E2E_RESULTS.md).

Проверки самого runtime можно повторить без запуска модели:

```sh

```

Промпт, модели и retrieval этой установкой не меняются. Разовый RAG smoke подтверждает работу перенесённого окружения; прежние [40 модельных проверок](../tests/rag/results/README.md) остаются отдельным историческим свидетельством качества. Локальная установка не подтверждает публичный production deploy, производственный SLA, многорепличную работу, автоматический backup или восстановление после потери диска.
